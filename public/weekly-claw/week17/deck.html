Theme 1

Skill creation became a managed workflow
Skill Workshop

Skills now move through pending proposals, guarded review, approve/reject/quarantine decisions, rollback metadata, and support-file approval.

Why it matters
  • Proposal lists, today actions, revision handoff
  • Searchable previews and review states
  • Locale coverage and reusable session routing
  • Visible what-changed, who-approved, what-allowed trail
What it changes
  • Skill creation stops being 'drop a markdown file and hope'
  • Reviewers can inspect support files and reverse installs
  • Skill lifecycle is auditable end to end

Theme 4

Long runs stopped leaving zombie sessions
Agent + Codex recovery

The runtime paid down the class of failures where the agent half-completes work and leaves the system in a half-state.

Runtime
  • Subagents keep cwd and workspace separation
  • Hook context stays prompt-local
  • Session locks release on timeout abort; live locks survive cleanup
  • Interrupted tool calls, stale bindings, compaction handoffs, auth-profile failover recover cleanly
Codex path
  • App-server and helper failures no longer tear down shared runtime state
  • Long-running delegated workflows have a clearer plugin/supervisor path
  • Fewer zombie sessions, fewer false live switches

Theme 7

Safety became runtime behavior
Fail closed, leave receipts

Malformed input rejected at the edge. Release, CI, Docker, and E2E lanes cap logs, response bodies, and probe waits.

Reject bad input earlier
  • Browser timeouts, viewport and tab indices, Gateway ports
  • Cron retry handling, Discord component ids, schema array refs
  • Telegram callback pages, channel progress callbacks
  • Next-train data-handling checks and unsupported-policy-key rejection
Proof lanes over vibes
  • Release, CI, Docker, E2E, plugin install, update, doctor, diagnostics, security lanes
  • Capped logs, response bodies, readiness probes, child workflow waits, artifact checks
  • Failures report bounded proof instead of hanging or false-greening

DX review

Easier to trust when state is visible
DX snapshot

DX moved the right direction. The next leverage point is cross-surface state coherence: UI, channel, provider, plugin, delegated runtime.

What improved
  • Providers time out more cleanly
  • Channels preserve final replies better
  • Mobile sessions keep more state

  • When one surface drifts, everyone needs one canonical explanation of model, auth, context, channel, and proof

Signal map

Three live questions for builders and maintainers
Three live questions

The weekly conversation should aim at operating discipline: safer installs, visible state, and proof packets that survive the chaos goblin phase of agent work.

Discuss live
  • Where should install policy be strict by default, and where should expert builders get escape hatches?
  • Which state should always be visible before a run starts: model, provider, auth profile, context budget, channel target, workspace, tools, policy scope?
  • What is the smallest proof packet every agent task should leave: artifact, command log, screenshot, commit, build, live check, reviewer receipt?
Watch next
  • Skill Workshop adoption: are proposals, review states, support-file approvals, rollback metadata actually used?
  • Mobile and channel durability: do final replies and approvals survive real Telegram, WhatsApp, iMessage, Discord, Talk usage?
  • Provider bounds: do timeout and catalog failures become understandable enough for non-maintainers to fix?

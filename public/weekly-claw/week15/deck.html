DevExperience priority 1

Telegram is still the trust surface

  • Clawtributors called Telegram release-critical: “releases are basically dead in the water if you can’t use Telegram.”
  • This week’s pain was specific: topic sessions turning tool-progress into final messages, generated-media/progress routing, overlapping DM replies, and disappearing send-message behavior.
  • AnswerOverflow support threads echo the same pattern: users want final-answer-only mode, topic routing clarity, and fewer preview/progress surprises.
  • Priority: treat Telegram topic/progress/media bugs as release blockers, not edge-case support trivia.

DevExperience priority 2

Auth and model mental models are overloaded

  • Users are still mixing runtime, provider auth, selected model, channel session, and memory behavior. Claude CLI / Max plan and ChatGPT Pro / Codex OAuth confusion kept surfacing.
  • AnswerOverflow shows recurring questions around Claude Max, Codex OAuth, setup-token, model status, and lossless-claw context behavior.
  • The fix is not “more docs” generically. It is one canonical setup path plus status that explains what is selected, why, and how to clear it.
  • Priority: make auth/runtime/model state explain itself in one screen and keep docs aligned with the current happy path.

DevExperience priority 3

Context and sub-agent cost became a security/product issue

  • Clawtributors debated whether subagents should inherit full AGENTS.md context or get a narrower subagents.md surface.
  • The concern was both cost and leakage: unnecessary memory/runbook context burns tokens and can expose operational detail if a subagent gets derailed.
  • AnswerOverflow has older but recurring subagent questions about allowed agents, workspace files, AGENTS.md injection, and token usage.
  • Priority: lighter child-agent context, clearer delegation defaults, and safer specialist workspaces.

DevExperience priority 4

Review loops are becoming product infrastructure

  • Goal Mode, ClawSweeper, Codex review loops, and “watch reviewer comments then fix until platinum” became normal community language.
  • That is good and dangerous: agentic review increases throughput, but it can also create infinite reminder/check loops and hidden work if not bounded.
  • The queue signal is clear: contributors want faster maintainer routing, clearer review state, and better automation that stops when done.
  • Priority: turn review automation into bounded flows with owners, stopping conditions, and visible status.

Follow-up ask

Make repro asks narrow

  • For auth/model issues: ask for provider, runtime, selected model, auth profile, and exact status output.
  • For Telegram/topic bugs: ask for channel type, topic id, message id, timestamp, streaming mode, and whether generated media/progress was involved.
  • For subagent/context issues: ask which files were injected, whether the child needed parent context, and token/cost evidence.
  • For review-loop issues: ask what started the loop, what stop condition was expected, and which PR/comment triggered it.

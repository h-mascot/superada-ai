# Linear access fallback for Cursor execution packs (2026-06-22)

## Trigger

Cursor stopped on `THE-176` with:

```text
Blocked before coding on THE-176.

Linear capability is missing in the environment:

• LINEAR_API_KEY / LINEAR_TOKEN: <REDACTED>
• linear CLI: missing
• Callable Linear MCP tools: not exposed here
```

That is correct fail-stop behavior. But the prompt itself had declared live Linear access as required for read paths. When the env key is unavailable, the run is dead before it starts.

## Lesson

Any project execution prompt that depends on a live external API (Linear, GitHub, Sentry, OpenAI, Notion, etc.) MUST declare a self-sufficient fallback shape so the agent can read state without the secret being present in the shell:

1. **In-repo data snapshot** under a documented, gitignored path.
   - Example: `<HOME>/Services/hoshi/.cursor/linear-live.json`.
2. **Helper script** that reads the snapshot first and re-fetches live only when the secret is in env.
   - Example: `scripts/linear/get_issue.py <ID> --format md|json|text`.
3. **Write-path queueing**: for actions that genuinely require the secret (proof comments, status transitions, label moves), do NOT fail-stop. Instead, queue the intended action body in the run-state file under `proofCommentQueue` (or analogous key) so a later Book/SuperAda session with the secret can post it.
4. **Block only when both snapshot and secret are missing.** The failure mode to surface is "data layer unavailable" not "secret missing."

## Prompt template addition (every cursor-goal-prompt.md and friends)

Insert this block after the authority order:

```text
## Linear access in this environment

`LINEAR_API_KEY` may or may not be present in the Cursor shell. Treat it as optional for read paths and required for write paths. Use the in-repo helper to read issue bodies and stay self-sufficient:

- Snapshot path: `<HOME>/Services/hoshi/.cursor/linear-live.json` (regenerated by Book whenever the live project changes; regen by running the helper with `LINEAR_API_KEY` set).
- Helper: `<HOME>/Services/hoshi/scripts/linear/get_issue.py <ID> --format md` (reads snapshot, falls back to live API when the key is available).
- For proof comments and issue status changes, the helper is read-only; write a `scripts/linear/post_proof_comment.py` if/when needed. Until then, do not attempt the write; record the comment body in `.cursor/hoshi-autonomous-run-state.json` under `proofCommentQueue` so Book can post it.

If neither snapshot nor key is available, do not guess. Mark the issue `BLOCKED` with `gate: preflight.linear_access` and stop.
```

## Helper script shape

```python
import argparse, json, os, sys, urllib.request
from pathlib import Path

SNAPSHOT = Path(__file__).resolve().parents[2] / ".cursor" / "linear-live.json"
PROJECT = "<linear project uuid>"

def fetch_live() -> dict:
    key = os.environ.get("LINEAR_API_KEY") or os.environ.get("LINEAR_TOKEN")
    if not key:
        raise SystemExit("LINEAR_API_KEY missing; falling back to snapshot at " + str(SNAPSHOT))
    # ... GraphQL project query with description bodies ...
    SNAPSHOT.parent.mkdir(parents=True, exist_ok=True)
    SNAPSHOT.write_text(json.dumps(project, indent=2))
    return project

def load_snapshot() -> dict:
    if not SNAPSHOT.exists():
        raise SystemExit("no snapshot at " + str(SNAPSHOT) + " and no LIVE key")
    return json.loads(SNAPSHOT.read_text())
```

Pitfalls when writing the helper:

- Do NOT echo the token in stderr or stdout. Use `os.environ` only.
- Tolerate `LINEAR_API_KEY` OR `LINEAR_TOKEN` — both names are used in the wild.
- When the live fetch succeeds, refresh the snapshot atomically (write to `.tmp` then rename) so a partially-written file does not get picked up by a parallel run.
- Surface a clean exit code: `0` for hit, `2` for not-found, `3` for both key and snapshot missing.

## Run-state contract

Add to `.cursor/<project>-autonomous-run-state.json`:

```json
{
  "linearAccess": {
    "mode": "snapshot-primary, live-fallback",
    "snapshot": "/path/to/.cursor/linear-live.json",
    "helper": "/path/to/scripts/linear/get_issue.py",
    "refreshed_at": "<ISO-8601>",
    "last_issue_checked": "<ISSUE_ID>",
    "note": "KEY may still be missing in the Cursor shell; the helper reads the snapshot first and only requires KEY for live re-fetch and for writing proof comments/status changes."
  },
  "proofCommentQueue": [
    { "issueId": "THE-176", "body": "<markdown>", "queuedAt": "<ISO-8601>" }
  ]
}
```

## When this fallback is wrong

- If the project has zero approved issues (queue is empty), there is no read dependency; do not require a snapshot. The fallback is only needed when there is at least one child issue to read.
- If writes are strictly forbidden by policy (e.g., a sandbox-only test project), do not bother queueing; queueing implies a future post.

## Verify

After dropping the helper + snapshot:

1. Run the helper with no key: it should read the snapshot and exit 0.
2. Run CLI Tester `request <ID> <branch>` in dry-run; it should produce `REQUESTED` without Linear.
3. Run the official validator: `python3 scripts/validate_execution_pack.py <pack_dir>` → `ok: true`.
4. Confirm `.gitignore` covers `.cursor/linear-live.json` so the snapshot does not get committed.

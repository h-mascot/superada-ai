When every crew member picks a different model for the same writing task, you get six voices and zero consistency. The writing-model-router fixes that by turning model preference into a shared skill that promotes cleanly across the whole crew.

## The Hook

A good writing model is not a personal secret. It is a crew asset. If Ada drafts in one model and Spock edits in another with no shared fallback rule, the output drifts and nobody can explain why. The router makes the choice explicit, portable, and verifiable.

## What Happened

On 2026-06-07 and 2026-06-08 we promoted the writing-model-router skill across the full crew: Ada, Book, Geordi, Scotty, Spock, and Zora. The promotion ran clean.

- **12 OK**
- **0 broken**
- **0 missing**
- **0 duplicate**

That is the number we care about. Six crew members, a two-day window, and a verification pass that found nothing broken, missing, or duplicated. The router is not a draft anymore. It is a shared skill that every crew member can call with the same expectations.

The promotion did three things at once. It standardized which model handles which writing stage. It defined what happens when the preferred model is unavailable. And it produced a receipt for every promotion step so the result was auditable rather than assumed.

## Why It Matters

Model preference is usually tribal knowledge. One person learns that a model handles long-form structure well, another learns it tends to over-format lists, and that knowledge never leaves their head. The next person re-learns it the hard way.

A shared skill ends that cycle. When the router promotes across the crew, the preference travels with it. Ada and Zora call the same routing logic, hit the same fallback when a model is down, and produce output that reads like it came from one coordinated team instead of six independent operators.

The fallback policy is the part that earns its keep. Models go offline. Rate limits hit. Versions get deprecated without warning. A writing pipeline that hard-codes one model breaks the moment that model blinks. A router with a defined fallback chain keeps producing, and it tells you when it had to fall back so you can decide whether the substitute output meets your bar.

The verification receipt is what makes the whole thing trustworthy. A promotion that says "done" with no proof is a promotion you have to re-check by hand. A promotion that emits a hash and a receipt per step lets you confirm the result in seconds and keep the record for later.

## Shared-Skill Rollout Checklist

Use this before promoting any writing skill across a crew.

1. **Define the skill surface.** Name the inputs, outputs, and the single entry point every crew member will call. If two crew members call it differently, it is not shared yet.
2. **Set the primary model per stage.** Drafting, editing, and final pass can use different models. Write down which model owns which stage so the choice is not improvised.
3. **Write the fallback chain.** For each stage, list the ordered substitutes. First choice, second choice, third choice. The router walks the chain until one responds.
